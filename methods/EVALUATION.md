# ATLAS 4 evaluation layers

Keep control correctness and research quality separate. Local unit tests measure deterministic code behavior; they do not establish live GitHub Copilot behavior, source completeness or factual accuracy.

Evaluate at distinct layers:

1. **Software controls:** lifecycle gates, authorization paths, hashes, migration/recovery, evidence and report checks.
2. **Live Copilot behavior:** repository instruction/skill discovery, actual tool availability, user authorization, stop-on-block compliance, task cancellation and observable model selection.
3. **Evidence and citations:** claim-level semantic support against original context, correct scope/dates/units, source independence, counterevidence and omission.
4. **Expert review:** blinded domain-specific judgment with disagreement adjudication and reviewer limitations.
5. **Decision calibration:** later real outcomes where defined forecasts and a sufficient sample exist.

No local fixture is a live research benchmark. Record failed, blocked, incomplete and retried cases in denominators. Use held-out domain-diverse inquiries, equal authorized resources, blinded outputs and prespecified measures. Report results per case with uncertainty; do not declare a universally best workflow from a small or synthetic sample. The [evaluation protocol](../benchmarks/PROTOCOL.md) describes trial design and current unverified claims.

When external APIs or Copilot surfaces are unavailable, label results offline and document the specific validation needed. No live Copilot, hidden model routing, authenticated MCP access, paid integration, calibrated quality, or research superiority is claimed by passing structural tests.
