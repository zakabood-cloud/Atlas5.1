# ATLAS 4: implemented research controls and remaining limits

This is a functional upgrade of the supplied ATLAS 3 repository, not a demonstration of universally best research. The complete supplied ZIP is preserved as `reference/ATLAS_Copilot_v3_baseline.zip` with SHA256 `048b48ce4e5379af0b1e1502b24b7469086b331aa8eb0c291fc0fe3c50b14deb`. [The file audit](FILE_AUDIT_V4.json) covers all 107 outer files and 40 embedded historical files. Historical reports and provider catalogs are retained as history, not current integration evidence.

## What changed

| Surface | Working implementation | Boundary |
|---|---|---|
| Copilot feature enablement | New-project ENABLEMENT stage records the observable capability inventory, verification receipts and explicit user decisions before research. Requested enablement stays blocked until verified or the user explicitly accepts a limitation. | Cannot toggle hidden settings, buy subscriptions, override administrator policies or guarantee unrestricted access. |
| Topic-specific MCP/access approval | Topic capability suggestions plus a required inquiry-specific access plan with publisher verification, permissions, privacy, cost, alternatives and quality impact; every proposed capability needs a user decision and every used capability a current test receipt. | Offline suggestions are not an exhaustive registry. A configuration file is not connected/authenticated access. |
| Every access block pauses work | Durable resource/operation/cause/quality-impact records and global holds; explicit scoped authorization for a retry or continuation with named gaps. Retry authorization does not unpause ordinary research. Live metadata failures and fixture worker access failures enter this path. | External Copilot tools must follow the operating instructions. Python does not intercept every tool or cancel independently running hosted jobs. |
| Parallel Copilot work | Dependency-safe task planning, declared disjoint writes/resources, actual client subagent handoffs, one state coordinator and observed execution/model-selection receipts. | `run-workers --worker fixture` remains synthetic, not a model launcher. More agents do not establish independence or better research. |
| Search and coverage | Fair dimension-first query allocation; primary and counterevidence searches for each dimension; explicit retrieval inclusion/exclusion records; coverage tied to logged searches and source-origin thresholds; recorded stopping criteria. | Counts and recorded searches do not prove exhaustive recall or methodological quality. |
| Evidence and review | Schema 2 claim scope and structured uncertainty; assessments bound to the exact claim and source snapshot; final review bound to the evidence register; validated DOI/declared source lineage. | Identity, source authenticity, semantic support and origin information still require real independent judgment. |
| Review packets and reports | Snapshot hashes checked before review; quote-centered context and explicit omitted ranges; report citation audit runs at the delivery gate, including bullet/table heuristics and omitted material claims. | Heuristics cannot detect every factual assertion or certify entailment. Non-text deliverables still need real rendering/format QA. |
| Evaluation | Duplicate/unknown IDs rejected; missing and failed cases retained in denominators; matched comparisons require identical answer keys; descriptive Wilson intervals, binary Brier/calibration coverage, frozen retrieval precision/recall/MRR/nDCG. | Selected controls are not representative factual-accuracy trials. Calibration requires actual observed outcomes. |
| Numeric analysis | Prevalidated simulation distributions, reversed clipping rejection, explicit v4 units and legacy calculation-engine reproduction. All ten synthetic examples remain executable. | Declared assumptions are not estimated forecasts; no general-purpose statistical or causal inference certification. |
| IO, ingestion and providers | Shared strict bounded JSON, streaming hashes, locators and explicit extraction omissions; strict bounded provider response schemas, cursor metadata and response digests. | PDF images/scans need visual inspection. Provider adapters are bibliographic metadata only and have not been live authenticated/tested. |
| Recovery, budgets and memory | Full staged bounded project archives, restore-to-new-only, explicit backed-up legacy migration, bounded worker timeouts/cancellation, persistent authorization ceilings and honest actual-overrun accounting, revalidated method-memory receipts. | Single trusted coordinator; not a malicious same-user race defense, encrypted backup, provider billing cap or durable remote execution service. |
| Copilot instructions | Coordinator/specialist profiles, read-only reviewer tool selections, staged skills and native Auto/default model guidance. | Client behavior, tool names, agent availability and model selection vary by surface, policy and plan. A role is not a model identity. |

New project contracts are schema 2. Existing schema 1 projects stay readable with explicit legacy status. Migration preserves a full quiesced backup and existing file bytes, reopens preparation and requires current feature/access approval and evidence review; it does not silently certify prior work. Registered numerical artifacts retain their explicit historical engine semantics.

## Evidence and validation

[Current testing](TESTING.md), machine-readable `test_results.json`, the supplied-v3 comparison output, `unittest.log`, and `package_validation.json` are generated from actual runs. Their observed counts and pass/fail states, not this descriptive report, are authoritative. Packaging requires the exact validated input inventory and independently extracts and checks the resulting ZIP. Baseline comparisons are selected deterministic engineering cases, including healthy controls, not measured general research superiority.

The prior narrow pushed revision passed 127 tests before these functional changes. That historical result must never be cited as validation of ATLAS 4. Synthetic fixture authors/reviewers, user decisions and access receipts are test data, not genuine independent review or authenticated providers. The eight domain research scenarios remain unrun as blinded live research trials.

Three actual Copilot implementation specialists worked alongside the coordinator on disjoint documentation, release-tooling and parallel-planning scopes after the user requested faster parallel execution. This establishes that delegation occurred in this session, not that every future Copilot client can launch those agents or that their hidden models differ.

The initial three specialist tasks were later reported cancelled without completion results or an exposed cause. Work was durably held instead of silently substituting single-agent implementation. The user explicitly authorized retries, three replacement launches succeeded, and exact external-tool observation receipts resolved the interruption holds. A successful launch receipt is not a completion receipt; specialist results are recorded separately.

## Access failures and approved gaps

Before the access-pause requirement was added, attempts to access Cochrane, PRISMA, ACL Anthology, arXiv and Anthropic originals failed DNS resolution. Those originals were not fully inspected. The user subsequently explicitly selected: "Continue this upgrade using accessible sources, explicitly document the gaps, and implement the mandatory MCP-approval and access-pause gates." This authorized continuation with those existing gaps, not retries, access-control bypasses or continuation after new failures.

Accessible official GitHub documentation and the ALCE authors' repository informed the prior preparation. Original methodological papers that could not be opened were not substituted with search summaries as verified evidence. An accessible older Crossref REST reference was marked deprecated and is not proof of present live API behavior. The upgrade's concrete engineering claims primarily rest on source inspection, reproduced defects and deterministic regression results.

No paid service, credential-backed metadata request or live cross-model comparison was performed. No private research content was sent to an unapproved provider. The repository code, offline comparisons and unit tests cannot establish actual Copilot Auto routing, authenticated MCP access, comprehensive web coverage, cross-platform reliability or expert-level research accuracy.

## Completion standard

The final release must pass the full local gate, reconcile the audit dispositions, record substantive review findings and remaining limits, and independently verify the packaged ZIP before publication. Publication is directly to the user-authorized `main`; an uncommitted implementation, candidate archive or earlier documentation push is not a completed full upgrade.
