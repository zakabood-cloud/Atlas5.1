# Access and failure behavior — ATLAS 5.1

- Network settings and project access plans are distinct. `atlas init` validates **only local** code; use `atlas doctor --network --host APPROVED_HOST` for an explicitly approved live DNS/TLS diagnostic. Actual search/MCP tests need provider-specific checks. A hostname resolving does not establish search API functionality.
- Reuse previously approved unchanged access needs. `access-approve` preserves matching valid access receipts for unchanged decisions and plan hashes. Sensitive access and paid calls always require current permission.
- `atlas access-test PROJECT NEED receipt.json` and `atlas access-renew PROJECT NEED receipt.json` store **operator-observed** tests; they do not make live network calls. The first authorized probe can run before a test receipt exists; substantive calls require a current receipt. Offline stage updates and completed task bookkeeping can proceed after receipt expiry; **new external execution still needs refresh**.
- Classify failures as **optional**, **critical**, or **security**. Optional retrieval gaps should not pause unrelated tasks or destroy successful capability receipts. Critical missing evidence pauses the affected decision and may require an explicit project hold; security incidents stop unsafe operations. `atlas access-block PROJECT ... --severity optional` reports that the gap was saved without a project-wide hold.
- Timeouts are different from authentication, network firewall denial, and paywalls. Retry transient errors only within a bounded, preapproved policy, retain failure receipts, and never retry blocked network egress indefinitely.
- Provisional search results may be saved as sources with `source_type=search_result`. They cannot independently substantiate material claims without originals.
- Consult optional GitHub Actions fetch relay (`optional_integrations/github_actions_fetch_relay/README.md`) only when approved by user and network policy. **Disabled by default.** No automated firewall bypass.
