# Capabilities and optional integrations

Status date: 2026-11-05. **No external provider in this catalog is connected, authenticated or runtime-tested by ATLAS.** Documentation retrieval is the only provider check performed. Prices and access policies can change; obtain an account-specific quote before spending. The shipped core performs no network requests and includes no credentials or executable MCP server.

## Operational capabilities

| Capability | Additional setup | Validation status |
|---|---|---|
| Intake ledger, gates, tasks, checksums, source/claim validation, calculations, memory, recovery | Python 3.10+; run extracted repository | Executed on Python 3.12.14/Linux; see validation report |
| Natural-language interview, methodology selection, browsing, synthesis | GitHub Copilot surface with repository instructions, skills, and the required authorized tools | Repository layout provided; real session unverified and feature support varies by client/settings |
| Independently authored verification | A distinct actual reviewer/model context and enough access to original sources | CLI enforces records and distinct labels, not real identity/independence |
| Optional commercial data and alternate research engines | Provider subscription/API entitlement and explicit authorization | Catalog/setup only |
| Presentations/spreadsheets/PDF rendering | Suitable local tools or authorized provider | Per-project capability check; no bundled universal renderer |

`python3 -m atlas doctor` checks executable presence and MCP configuration names. It does not authenticate, test network access, read environment secret values or send requests. Parsing `.mcp.json` may encounter credentials if you put them there; values are neither reported nor used. Prefer proper provider credential storage and keep secrets out of project configuration.

## Connect an optional tool responsibly

1. Start from a mandate-specific data gap, not a general desire for more tools. Estimate which decision could change if the data becomes available.
2. Check the current official provider page, marketplace/geography, retention, API quota, costs and permission scopes. A subscription to a chat app does not establish separate API entitlement.
3. Get authorization for any additional spending or disclosure. Use the provider's normal account/OAuth/key setup; do not paste credentials into reports, source files, shell history or model prompts.
4. If using MCP, inspect the server publisher, transport, permission scope and package version. Prefer an official service over an unreviewed community executable. No global tool preapproval is supplied here.
5. Configure optional MCP tools only through the supported setup for the Copilot client you are using. Review the server publisher, transport, permission scope, and package version. Confirm scope and authentication in the current client before use. Do not put an API key in a URL or commit credentials.
6. Inspect `doctor` and the client's MCP status. After current approval, run one authorized, non-sensitive representative read-only query, fetch its original source, and check extraction, dates, latency, actual cost and error behavior. Optional source failures should be documented without stopping unrelated work. Critical and security failures hold the affected work and consequential decisions. Only policy-authorized, bounded retries for transient read-only requests may be attempted; never blindly resubmit a chargeable submission after an ambiguous timeout.
7. Record a capability observation in `readiness.json`: name, status, observed_at, expires_at, method, limitations and an `evidence_artifact` for authenticated/tested status. Save a redacted receipt. The CLI checks these fields and expiry; the observer remains responsible for truthful status.
8. Import only needed source text and provenance into the project registry, preserving retrieval limitations. If access fails, record a limited check with a meaningful fallback, or leave readiness blocked.

No Copilot-specific network adapter is shipped. The tested interface is the local capability/evidence artifact contract. It accepts results from authorized Copilot tools, provider exports, or independently reviewed scripts without claiming to execute those services. This avoids unchecked billing, hidden retries, and outdated SDK assumptions; it also means an authenticated adapter is additional work when programmatic access is required.

## Tool selection decisions

Use public primary sources first when they answer the decision question. Add commercial tools for otherwise unavailable historical/granular coverage and test their incremental value on a representative sample. For a UAE Amazon opportunity, US estimator coverage is insufficient; use supported local marketplace evidence, actual approved account data, supplier quotes and conservative scenario bounds. For Shopify versus Amazon, reconcile channel-specific acquisition, tax, returns, fees and working capital with the same product/geography/horizon. For scientific reviews, use appropriate domain databases and record-level screening; an AI report's paper limit must not silently truncate the eligible evidence set.

Provider confidence is not calibrated probability. Independent engines can share the same search index or original source. Preserve original-origin groups and trace shared reports before interpreting agreement.

## ATLAS 3.0 actual bundled adapters (2026-11-03)

`atlas/adapters.py` implements two **opt-in read-only** search endpoints for bibliographic metadata: Crossref (`api.crossref.org/works`) and OpenAlex (`api.openalex.org/works`). They are bounded, hostname-allowlisted, redirect-rejecting and require `--live` plus approved topic access. `--probe --limit 1` without pagination is a narrow preparation-stage test; substantive searches are RESEARCH-only and require `--plan-id` with the exact accepted query. Each attempted request is saved under the project and hash-bound; successful results must also be linked from the matching search-log row. Failures trigger the global hold. These adapters are not general crawlers or full-text retrieval. No live request is claimed by this documentation. OpenAlex may charge for metered searches depending on account/usage; check terms before use. Other listed commercial integrations remain candidates requiring separate implementation and authorization; they are not connected by the mere presence of this catalog.

The local scheduler has only a synthetic fixture worker. Real research should be performed by the active Copilot session using only its authorized, actually available tools; record task outputs and evidence through the local ledger. ATLAS does not spawn a separate Copilot or other model CLI.
