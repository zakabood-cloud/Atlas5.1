Read status, approved enablement/access decisions, protocol, readiness and `methods/ORCHESTRATION.md`. Build plan.json with a dependency DAG, owners, explicit evidence requirements, disjoint write paths/resources and approved access IDs. For GitHub.com cloud-agent work, use native Auto at task start when the picker is available; otherwise follow the client default. Leave custom-agent `model` unset. Record the selection shown for each task and the actual routed model only when exposed; otherwise say `not exposed`. Agent definitions are advisory specializations, not model identities or permission boundaries; use only actually available tools.
Advance to RESEARCH. `python3 -m atlas dispatch-plan <id> --max-workers 4` recommends ready work only; planning more than one worker requires current user-approved, observed enabled subagents. If unavailable, accepted as a limit or not approved for use, plan with one worker. The coordinator rechecks gates and launches actual agents through client tools; it alone reserves tasks via `task <id> <task-id> running`, persists structured JSON handoffs and marks completion with an output path. Do not use the synthetic fixture worker for research. No simultaneous coordinator writers. Failed tasks require deliberate retry and have at most three starts; no automatic retry or fallback after an access block.
Record every meaningful query in search_log.json including failures, access blocks and explicit inclusion/exclusion for each retrieved record. Populate source snapshots, schema-2 evidence.json, calculations and coverage.json. Use `quant` only when its declared assumptions match the question; specialist statistics require separately validated code. Persist raw data only as permitted, with metadata and hashes. Revisit conflicting explanations and decision-reversing assumptions. Classify the failure: optional source gaps do not pause unrelated research; critical/security failures block affected decisions. Authorized bounded transient retries are allowed; see docs/ACCESS.md. Stop per protocol when criteria are met or the user explicitly accepts a documented gap; label access-limited results. Advance to VERIFY only when planned tasks and coverage accounting are complete.
